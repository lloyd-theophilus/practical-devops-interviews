# AWS S3 Interview Questions & Answers

---

**Q: S3 bucket access suddenly fails. What areas will you investigate?**

**A:**
S3 access failures can originate from several independent layers. Work through them systematically:

**1. Confirm the error type**:
```bash
aws s3 ls s3://my-bucket/ --debug 2>&1 | grep -E "HTTP|Error|Access"
```
The HTTP status code tells you a lot:
- `403 Forbidden` → permissions problem (IAM policy, bucket policy, ACL, Block Public Access, KMS key policy).
- `404 Not Found` → bucket or object doesn't exist, or the bucket name/region is wrong.
- `503 Slow Down` → request rate exceeded; implement exponential backoff.
- Connection timeout → VPC endpoint or DNS issue.

**2. IAM permissions**:
- Check the identity making the request has the required S3 actions (`s3:GetObject`, `s3:PutObject`, `s3:ListBucket`, etc.) on the bucket and object ARNs.
  ```bash
  aws iam simulate-principal-policy \
    --policy-source-arn arn:aws:iam::ACCOUNT:role/MyRole \
    --action-names s3:GetObject \
    --resource-arns arn:aws:s3:::my-bucket/myfile.txt
  ```
- For EC2: verify the instance profile is attached and the role has the correct policy.
- For cross-account: both the IAM policy (caller's account) AND the bucket policy (bucket's account) must allow the action.

**3. S3 bucket policy**:
```bash
aws s3api get-bucket-policy --bucket my-bucket
```
Check for explicit `Deny` statements — these override `Allow` rules. Common culprits:
- `aws:SecureTransport: false` deny (blocks HTTP, only HTTPS allowed).
- IP condition (`aws:SourceIp`) that no longer matches your egress IP.
- `aws:PrincipalOrgID` condition that excludes the calling account.

**4. S3 Block Public Access**:
```bash
aws s3api get-public-access-block --bucket my-bucket
```
If `BlockPublicAcls`, `IgnorePublicAcls`, `BlockPublicPolicy`, or `RestrictPublicBuckets` are `true`, public access (and sometimes cross-account via bucket policy) is blocked regardless of the bucket policy content.

**5. S3 Access Control Lists (ACLs)**:
```bash
aws s3api get-bucket-acl --bucket my-bucket
```
If Object Ownership is set to `BucketOwnerEnforced`, ACLs are disabled and all access is controlled by policies — this is the AWS-recommended setting. If ACLs are still in use, verify the object ACL grants the required access.

**6. KMS encryption**:
If the bucket uses SSE-KMS, the caller needs `kms:GenerateDataKey` (for writes) and `kms:Decrypt` (for reads) on the KMS key:
```bash
aws kms get-key-policy --key-id <key-id> --policy-name default
```
For cross-account access, add the external account/role to the key policy explicitly.

**7. VPC Endpoint policy** (if accessing from a private subnet via S3 Gateway Endpoint):
```bash
aws ec2 describe-vpc-endpoints --filters Name=service-name,Values=com.amazonaws.us-east-1.s3
```
Check the endpoint policy — a restrictive endpoint policy can block access even if IAM and bucket policies allow it.

**8. Bucket region**:
S3 requests to a bucket must go to the correct regional endpoint. If using path-style URLs or old SDKs, a region mismatch returns a `301 PermanentRedirect` or `400 Bad Request`:
```bash
aws s3api get-bucket-location --bucket my-bucket
```
Configure the AWS SDK/CLI to use the correct region: `AWS_DEFAULT_REGION` or `--region`.

**9. Recent changes (change management review)**:
- Was a bucket policy or IAM policy recently modified?
- Was a Service Control Policy (SCP) at the AWS Organization level changed?
- Was the KMS key rotation or key policy updated?
- Was Block Public Access enabled at the account level (affects all buckets)?
  ```bash
  aws s3control get-public-access-block --account-id 123456789012
  ```

**Summary checklist**:

| Check | Command |
|---|---|
| IAM policy simulation | `aws iam simulate-principal-policy` |
| Bucket policy | `aws s3api get-bucket-policy` |
| Block Public Access | `aws s3api get-public-access-block` |
| KMS key policy | `aws kms get-key-policy` |
| VPC endpoint policy | `aws ec2 describe-vpc-endpoints` |
| Bucket region | `aws s3api get-bucket-location` |
| Account-level BPA | `aws s3control get-public-access-block` |
